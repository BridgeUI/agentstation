# ダッシュボードの構造改善案（App Store Connect 風）

**2026-11-01 採用・実装済み。** トンマナは `design/README.md` に、UI は `worker/public/` と `worker/ui/` に反映した。このフォルダのモックは参照用（本番は `wrangler dev` で見る）。

2026-11-01。現行の `worker/public/` を実データ相当の seed（`worker/ui/dev-seed.sql`）で表示して測った結果と、それをもとにした改善案。モックは同じフォルダの `index.html`（一覧）と `host.html`（各環境）。素の HTML/CSS なので、ブラウザで開けばそのまま見られる。

## 1. 現状の問題

幅 1024px で測ったページの高さ。

| 画面        | 高さ    | 内訳                                                                                                        |
| ----------- | ------- | ----------------------------------------------------------------------------------------------------------- |
| 一覧        | 2,964px | 全体の棒グラフ 6 本（780px）＋ 環境カード 3 枚（1,170px、2+1 で折り返す）＋ 履歴表                          |
| Taro の環境 | 3,917px | 接続 480px ＋ SSH認証 330px ＋ ログイン情報 410px ＋ 操作 500px ＋ フォルダRC 370px ＋ **基礎設定 1,500px** |

原因は 3 つ。

1. **すべてのセクションが常時展開**。各環境の画面は 7 セクションを縦に並べていて、「いま何が問題か」を見るだけでも全体をスクロールする。基礎設定は OK の 18 件も毎回表示される。
2. **同じ情報を 2 回描いている**。一覧の「Mac mini 全体」は使用量と配分で棒グラフを 6 本描き、さらに各環境カードでも CPU・メモリ・ディスクの棒を 3 本ずつ描く。
3. **カードが縦長**。環境カードは 4 行の状態＋3 本の棒＋ボタンで 1 枚 560px。3 枚を横に並べられる幅がないと 2 段になる。

App Store Connect が読みやすいのは、(a) 見出しは小さく薄く、数値と状態が主役、(b) 一覧は表、詳細はタブ、(c) 1 画面に出すのは「判断に必要な数字」だけで説明や履歴は 1 階層下、という構造のため。この 3 点を取り入れる。

## 3. 一覧（`index.html`）

高さ 2,964px → **1,186px**（60% 減）。

1. **見出し**：「一覧 ● すべて正常」＋「Mac mini · 3環境 · 最終受信 1分前 · CPU 10コア · メモリ 24GB · SSD 512GB」。スペック行は配分カードから移動。
2. **注意**：1 行バナー「Taro の環境：手動の基礎設定が 2 件未完了 → 基礎設定を開く」。リンク先は `host.html#setup`。
3. **環境（表）**：環境カード 3 枚を表 1 つに。列は 環境（アバター・名前・host/アカウント/最終受信）／状態／Claude Code／Remote Control／Codex／VM・エージェント／CPU／メモリ／ディスク。行クリックで環境の画面へ。スマホ幅では 4 つのプロセス列を隠し、環境・状態・使用量だけ残す。
4. **Mac mini 全体（タイル 3 枚）**：CPU・メモリ・ディスクを 1 枚ずつ。数字（38%）＋補足（13.4 / 24 GB）＋積み上げバー＋内訳 1 行。「配分（設定）」はセグメントで切り替え、5 行 × 3 列の表で見せる（棒 3 本をやめる）。
5. **最近の動き**：操作履歴とイベントをセグメントで切り替える 1 パネルに。最新 5 件＋「すべての履歴を表示（32件）」。

## 4. 各環境の画面（`host.html`）

高さ 3,917px → **概要タブ 1,081px、基礎設定タブ 845px**（タブごとに 1 画面前後）。

**見出し**：アバター＋「Taro の環境」＋状態ピル。右に接続ボタン 2 つ（SSH・画面共有のブラウザ版）。いちばん使う操作を最上部に置き、接続タブまで行かなくても入れるようにする。メタ行に Claude Code のバージョンを出す（現行は右カラムの下の方）。

## 5. 実装の順番（影響範囲つき）

UI の変更だけで API・D1・エージェントは触らない。`worker/ui/*.ts` と `worker/public/*.html`、`style.css` が対象。

1. **基礎設定を畳む**（`envpage.ts` の `renderSetup`、CSS に `details.fold`）。これだけで環境画面が約 1,000px 縮む。他と独立。
2. **一覧の環境カードを表に**（`overview.ts` の `envCard` → `envRow`、`index.html` の `#env-grid` を `<table>` に）。`judge.ts` の `rows()` はそのまま使える。
3. **全体の棒 6 本をタイル 3 枚＋配分表に**（`renderUsage` / `renderAlloc`）。セグメントの状態は `localStorage` でよい（`explainOpen` と同じ扱い）。
4. **環境画面をタブに**（`host.html`/`vm1.html`/`vm2.html` の構造変更。ハッシュで切り替え、`main.ts` で `hashchange` を拾う）。既存の `id` はそのまま残せば `renderXxx` の変更は最小。
5. **接続・SSH認証・ログイン情報の統合**（`renderConnection` / `renderSshUsers` / `renderLogin` を `renderAccount` に）。
6. **見出し・タイポグラフィの縮小**（CSS のみ。h1 24px、h2 17px、本文 14px）。最後にまとめて当てると差分が追いやすい。

1〜3 は現行の HTML 構造のまま入れられるので先に出せる。4 以降は 3 ページの HTML を同時に変えるため、1 コミットにまとめる。

## 6. 決めてもらいたいこと

- **タブか、1 ページ＋目次か**。モックはタブ。スクロールで全部見たい派なら、sticky の目次（アンカー）＋基礎設定の折り畳みだけでも 3,917px → 約 2,400px にはなる。
- **一覧から棒グラフを完全になくすか**。タイルに 6px のバーは残しているが、これも消して数字だけにすると App Store Connect にさらに近づく。
- **接続ボタンを見出しに置くか**。本人・オーナーだけに出す前提。閲覧者には出さない。

## 7. スマホ・二画面・PWA（2026-11-01 追加）

決めごとは `design/README.md` の「スマホ・二画面・PWA」に。アイコンは次で生成した（PIL が無いので Swift）。

```bash
# 白地の正方形にロゴを中央配置。最後の引数はロゴの占める割合
swiftc -O mkicon.swift -o mkicon
./mkicon worker/public/logo.png worker/public/icons/icon-192.png 192 0.72
./mkicon worker/public/logo.png worker/public/icons/icon-512.png 512 0.72
./mkicon worker/public/logo.png worker/public/icons/icon-maskable-512.png 512 0.55
./mkicon worker/public/logo.png worker/public/icons/apple-touch-icon.png 180 0.72
```

`mkicon.swift` は CoreGraphics で白を塗ってから `CGContext.draw` するだけの 30 行。リポジトリには入れていない（必要なら `mac/tools/` に置く）。
